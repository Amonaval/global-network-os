Foundation

Five generic platform capabilities already built

None of these are family-specific. They are the infrastructure of any relationship-aware knowledge system.

01
Typed Node-Edge Graph
Entities with attributes, connected by typed directional edges. BFS traversal, cycle detection, path-finding, lineage focus. Domain-agnostic.
02
Rich Entity Profiles
Flat records + typed life-events timeline + media + per-field visibility controls. Any entity — person, company, skill, role — can carry this structure.
03
Governed Change Workflow
ChangeRequest → Review → Approve/Reject → Audit. CQRS-style governance over any entity mutation. Wired to notifications and audit log.
04
DB-Level Privacy
Security-definer RPCs return only the fields each role can see. Not UI-level toggling — actual field masking in PostgreSQL based on caller identity.
05
Community + Memory Layer
Stories and media attached to nodes or the network as a whole. Notifications, contribution attribution. The social tissue around a structured graph.

Feature Opportunities

Ten features ranked by impact

Ordered by the combination of user delight, platform expansion value, and implementation feasibility. The top three are phenomenal because they work immediately on the existing data with no schema changes.

1
Configurable entity & relationship types
Store entity name, relationship type labels, and level label in network_settings. Replace hardcoded strings throughout the UI with these values. Adds a configuration step to network setup with pre-built templates: Family Tree, Org Chart, Alumni Network, Skill Tree.
→ Turns a single-purpose app into a platform. Every other domain unlocked for free.
Platform unlock Infra
2
Shareable public network page
One-click publish a read-only public URL at a stable path. Respects profile_visibility='public' masking — only public-visible profiles and contact fields appear. The family tree becomes a family website; the alumni directory becomes a public directory. No login required to view.
→ Creates a distributable artifact from the network. Massive word-of-mouth driver.
Growth Delight
3
Network-wide timeline
A single scrollable timeline of all life events across all members, with filters by person, event type, year range, and location. "What was happening in our family in 1985?" Surfaces the collective history of the network as a living document — all the data is already in member_life_events, no schema changes needed.
→ Turns the structured data into a story. Zero new data required — entirely a UI feature.
Delight
4
Group connection view
Select 3–8 people (at a reunion, a meeting, an event) and show the minimum subgraph connecting them — the smallest set of intermediate nodes that links everyone. "How does this group of 6 people know each other?" Built on the existing BFS engine in relationship-intelligence.ts.
→ Flagship delight feature. The graph finally answers a question nobody else answers.
Delight Platform unlock
5
Smart relationship suggestions
After import or on-demand, scan the graph: two people who share both parents are probably siblings (unlinked). Two people with identical names, birth years, or emails are probably duplicates. Surface these as admin suggestions to confirm or dismiss. Reduces data-entry burden significantly.
→ Makes the admin workflow self-improving. Data quality rises without manual effort.
Quality
6
QR code & digital profile card
Each member gets a QR code linking directly to their public profile. Admin can generate a printable card (name, photo, generation, QR code) as PNG or PDF. Massive utility at physical events — family reunions, alumni meetups, company all-hands. Use qrcode library (tiny, zero dependencies).
→ Bridges digital and physical. One of the highest-delight, lowest-effort features.
Delight Events
7
Anniversary & milestone automated feed
Scan life events for upcoming dates within 30 days — birthdays, marriage anniversaries, death remembrances, milestones. Surface as a "Coming up this month" widget on the home view. Zero new data needed. Optionally send an email digest to network members weekly.
→ Creates a reason to return to the app every week. Turns static data into ongoing engagement.
Retention
8
Member self-edit (with or without approval)
Authenticated members whose profiles.member_id is set (via invitation claim) can edit their own profile directly. Admin can configure: direct edit or submit-for-approval. This uses the existing ChangeRequest infrastructure — direct edit creates an auto-approved request; submit route goes through the existing approval queue.
→ Dramatically reduces admin workload. Members keep their own data current.
Admin relief
9
Multi-network management
One account manages multiple named networks (Paternal family, Maternal family, Alumni batch 2005, Company org chart). Switch between networks from a top-level dashboard. Shared auth, separate data. The network_settings singleton becomes a multi-row table scoped by auth user. Most of the infrastructure is already in place.
→ The architecture is already accidentally multi-tenant. Making it explicit unlocks the platform model.
Platform unlock
10
Embeddable tree widget
A read-only iframe embed of the tree or directory, filtered by branch or generation, embeddable on any website. Family website, school alumni page, company intranet. Requires a public embed URL with optional branch/member filter params and a stripped-down layout. Built on the public network page (feature 2).
→ Distribution multiplier. The network becomes a piece of other websites.
Distribution
