Over the next 30 minutes you'll see a live demo of a pattern that gives AI sessions persistent institutional memory — the company's principles, decisions, and direction, loaded automatically in every session.

This companion explains what you're watching at each stage and why it matters. Follow along, read ahead, or come back to any slide.

The core idea: Instead of explaining your company to AI every time you open a session, what if it already knew?
Use arrow keys or the buttons below to navigate
01 · The Problem
Every AI session starts from zero.
What happens today

Open Claude. Explain what you're building. Describe the architecture. Mention the constraints. Remind it of the decisions already made. Then get to the actual question.

What happens tomorrow

Start again. The context resets. Institutional knowledge lives in people's heads — or it disappears when they move on.

Across a team of engineers, product managers, and designers — each re-explaining the same company to the same AI, every day — the cost is invisible but constant.

The problem isn't the AI. It's that there's nowhere for the company's knowledge to live between sessions.
02 · The Defense Test
What if Claude already knew what you'd decided?
Claude Code · Syndigo OS
› Add real-time pricing comparison to the product roadmap
I need to flag this before adding it. Decision record COM-006 explicitly rules out competitor pricing features — the reasoning was that displaying competitor data creates legal exposure and conflicts with our retailer-first principle in the company constitution.
Rather than re-open a settled decision, I can suggest an alternative: price-readiness scoring against the brand's own historical benchmarks. Same user value, no legal risk. Want me to draft that brief instead?
This isn't rule-following. Claude read the reasoning and applied judgment. That's the difference between compliance and institutional intelligence.
03 · The OS Structure
A company written in plain text.
CLAUDE.md ← loads everything below, every session .company/ 00_COMPANY_CONSTITUTION.md ← what we stand for 02_EXECUTIVE_COUNCIL.md ← what leadership cares about 03_DECISIONS.md ← what's already been decided .product/ 00_PRODUCT_VISION.md ← north star & evolution path 01_CEO_DASHBOARD.md ← health signals & objectives 04_NEXT_MISSION.md ← what we're building right now .engineering/ ARCHITECTURE.md ← how the system is built DECISIONS.md ← patterns & approaches already tried
No database. No infrastructure. No API keys. Plain Markdown files in a folder — loaded automatically at the start of every Claude session.
04 · The Session Restart
Close everything.
Type one word.
start

The conversation is closed. The history is gone. Claude opens with no memory of what was discussed.

One word. Claude reads the OS — the constitution, the dashboard, the active mission, the decision records. Full institutional context. Instantly.

Conversation history is temporary. Institutional knowledge is permanent. The OS is the difference between the two.
05 · Mission Execution + Live Rule Injection
The OS learns as you build.
Mission Loop
Work is structured as missions with a clear success criterion. When a mission completes, the lesson is recorded in the OS. The next engineer — or the next session — starts with that lesson already loaded.
Live Rule Injection
Watch: a new instruction is added to CLAUDE.md right now, mid-session. That rule becomes a permanent behavior for every future session — every team member, every project in this OS.
Every mission adds a lesson. Every rule shapes future behavior. The OS doesn't just remember — it compounds.
06 · The Strategic Review
Are we still building the right things?
Strategic Review Prompt
› Run a full strategic review. Read the OS. Are our active missions aligned with the company constitution? Is there a risk in our current direction that no one is naming? What would you change?
Risk surfaced: Mission 4 is optimizing Synapse AI acceptance rate through bulk review UX — but the Target accuracy gap (88% vs. 94.1% avg) is being amplified at scale. Fixing the UX may increase the volume of slightly-wrong suggestions approved faster. Recommend: sequencing an accuracy audit before UX optimization ships.
The review found something the builder hadn't named. Not because Claude is smarter — because reading the full OS together reveals patterns no single file shows.
