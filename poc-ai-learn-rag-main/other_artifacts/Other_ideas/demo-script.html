Presenter mindset

This room has power users. Skip the "here's why Claude is useful" entirely. They know. Move at the pace of an expert talking to experts. The goal is not to teach — it's to show something they haven't seen. The moments that land are the ones they couldn't have predicted. Engineer those moments, then get out of the way and let the silence work.

For the experts — the distinction that matters
The difference between a CLAUDE.md file and this OS is the same difference between a comment and an architecture. A single md file tells Claude how to respond. The OS tells Claude how to think — with hierarchy, guardrails, history, and direction all encoded into a coherent structure.

Template — how to create the OS for any product or company

🗂
Setup in 3 steps — 15 minutes for any context

What you provide

  • Company or product name
  • Public website / docs URL
  • Objective scores (BetterWork, OKRs, whatever you track)
  • Any internal docs you have (optional — upgrades accuracy)

What gets generated

  • Company constitution (principles that never change)
  • CEO dashboard with your actual objectives
  • Product vision + north star metric
  • Engineering architecture + decision records
  • First mission queue ready to execute
The setup prompt (copy SETUP_PROMPT.md):

I want to create an AI Company Operating System for [COMPANY_NAME].

STEP 1 — Research: Search [COMPANY_WEBSITE] and gather: what they do, who their customers are, competitive moat, technical architecture, recent strategic moves.

STEP 2 — Objectives: [PASTE YOUR OBJECTIVE SCORES HERE]

STEP 3 — Using the template at [TEMPLATE_PATH], create a complete OS at [OUTPUT_PATH]. Replace every [PLACEHOLDER]. Every sentence must be company-specific — no generic filler.

Chat deflections — one-liners for live questions

Expert audiences ask good questions at the wrong moment. Drop these in chat to keep momentum. Most questions resolve themselves as the demo continues — let them.

They ask…Say this (one line)
"What about confidential data?"

 All files are local — a folder in your repo under your git control. Nothing is transmitted anywhere.
"How is this different from a CLAUDE.md?"
Real question: I already do this, what's new?
 A CLAUDE.md tells Claude how to respond. The OS tells Claude how to think — with hierarchy, history, and strategic memory across every session.
"How do you keep it updated?"

 The mission completion rule updates it. The strategic review updates it. It's the output of the workflow, not extra work on top of it.

 This doesn't replace those. It bridges them — permanent decisions distilled into what Claude actually reads. Confluence is the archive. This is the active brain.

 Plain markdown — model-agnostic. Claude Code is the best environment for it today. Any future AI that reads files works the same way.
