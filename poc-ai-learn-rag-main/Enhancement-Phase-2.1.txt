 Top 5 Major Leap Enhancements

 🚀 Leap 1 — Streaming Responses

 Biggest perceived-performance win. Every modern AI tool has this.

 Current state: askOllama() in src/rag/query.js (line 120) uses stream: false. Full response buffered before client sees anything. Waits 15–90 seconds of silence.

 What changes:
 - src/rag/query.js → askOllama: set stream: true, read newline-delimited JSON stream from Ollama, yield tokens via async generator
 - src/api/server.js /api/chat → switch from res.json() to text/event-stream, flush token SSE events, send final metadata (sources, debug) in the last event
 - public/js/app.js → replace fetch + await json() with response.body.getReader() loop, append each token to the answer bubble as it arrives
 - Claude provider: use stream: true in the Anthropic messages call

 Effort: ~1 day. No new dependencies.

 ---
 🚀 Leap 2 — Local Document Upload (PDF, DOCX, ZIP, MD)

 Removes the crawling requirement entirely. Users drag-drop their own docs.

 What it enables: Someone with a folder of API specs, runbooks, onboarding docs, or exported PDFs can index them in 30 seconds without configuring a portal URL. This is the "Notion AI for your own files" use case.

 What changes:
 - New "Upload Documents" section in the setup wizard OR a persistent "Add docs" button in the chat UI sidebar
 - POST /api/docs/upload endpoint (multipart) — accepts PDF, DOCX, MD, TXT, ZIP
 - PDF text extraction: pdf-parse npm (pure JS, no native build needed)
 - DOCX extraction: mammoth npm (pure JS)
 - ZIP: unzip with adm-zip (pure JS), process contained docs
 - Files saved to docs/uploads/<filename>/ with a synthetic manifest entry
 - Existing ingest.js pipeline picks them up — no changes to embedder/store
 - UI shows upload progress and "indexed N chunks from filename.pdf"

 Effort: ~2-3 days. Three pure-JS deps.

 ---
 🚀 Leap 3 — Incremental Re-crawl (Change Detection)

 Full rebuild from scratch on every run is the #1 operational pain point.

 Current state: ingest.js re-processes every manifest entry on every run. crawl.js re-fetches every page. No checksums anywhere.

 What changes:
 - Crawl side (src/crawler/crawl.js): compute MD5(html) for each saved page. Add contentHash field to manifest entries. On re-crawl, skip fetch + save if hash matches data/crawl_hashes.json (URL → hash map). Write changed pages only.
 - Ingest side (src/ingestion/ingest.js): read data/ingest_hashes.json (file → hash). Skip embedding if contentHash matches last run. Upsert only changed chunks.
 - Result: Typical re-crawl on a large portal (500 pages, 5% changed) drops from 45 min → 3 min.
 - New CLI: npm run crawl -- --incremental (default after first build; --full to force)

 Effort: ~1-2 days. Uses built-in crypto.createHash('md5').

 ---
 🚀 Leap 4 — Multi-Source Integration via OAuth (Confluence, Google Drive, Notion)

 Removes the portal-URL + credentials requirement. Users connect apps they already use.

 What it enables: A user clicks "Connect Confluence", OAuth flow runs in a browser window (no credentials stored), the app fetches pages directly from the Confluence REST API. Same for Google Drive and Notion.

 Architecture:
 - New integration wizard step: radio cards — "Web Portal (crawl)" | "Upload Files" | "Confluence" | "Google Drive" | "Notion"
 - Per-integration adapter pattern: src/integrations/confluence.js, src/integrations/gdrive.js, etc.
 - Each adapter implements fetchPages() → returns { title, url, html, metadata }[]
 - OAuth flow via Playwright or Electron shell (open browser → get token → save to config)
 - Confluence: uses Space Key + page tree via REST API (no crawling, structured data, faster)
 - Google Drive: fetch Docs/Sheets as exported HTML; index folder recursively
 - Confluence adapter is largely portable from cr2 — it already has the REST API logic

 Effort: ~1 week per integration. Confluence first (most requested for enterprise).

 🚀 Leap 5 — Evaluation Harness + Analytics Dashboard

 The only way to know if the knowledge base is actually good. Enterprise buyers need this.

 What it enables: After N queries, see: answer rate %, top unanswered questions (documentation gaps), which sections are referenced most, average confidence scores, latency trends.

 What changes:
 - src/rag/query.js: append each query result to data/eval.jsonl — { ts, question, topSemScore, latencyMs, blocked, sectionsUsed, chunkIds }
 - src/rag/eval.js (port from cr2, already built there): CLI with --blocked (gap analysis), --summary, --tail N
 - New "Analytics" tab in the chat UI (public/index.html):

   - Top 10 unanswered questions (blocked queries)
   - Most-referenced sections bar chart
   - Last 20 queries with score badges
 - The "blocked queries" list is the most valuable thing — it tells users exactly what documentation they're missing

 Effort: ~2 days (eval.js exists in cr2; Analytics tab is new HTML/CSS/JS).

 The npm run sync Error — Root Cause & Fix                                                                                                                                                                                                                        Error: DOCS_BASE_URL is not set. Cannot start.

 Why: npm run sync runs node src/crawler/crawl.js --incremental directly from the terminal.
 The crawler reads config from environment variables (set in .env). But the Electron/wizard app                                 stores its config in data/app_config.json — not .env. When the server spawns the crawler, it
 calls configToEnv(cfg) and passes those env vars to the child process. When you run npm run sync                                directly, that wiring doesn't happen — so DOCS_BASE_URL is never set.

 Fix needed: Create scripts/sync.js — a thin wrapper that reads app_config.json, calls
 configToEnv(), and spawns crawl + ingest with the right env vars. Update the sync npm script
 to use it. This is the only code change needed from this session.

 Top 5 Major Leap Enhancements

 🚀 Leap 1 — Streaming Responses

 Biggest perceived-performance win. Every modern AI tool has this.

 Current state: askOllama() in src/rag/query.js (line 120) uses stream: false. Full response buffered before client sees anything. Waits 15–90 seconds of silence.

 What changes:
 - src/rag/query.js → askOllama: set stream: true, read newline-delimited JSON stream from Ollama, yield tokens via async generator
 - src/api/server.js /api/chat → switch from res.json() to text/event-stream, flush token SSE events, send final metadata (sources, debug) in the last event
 - public/js/app.js → replace fetch + await json() with response.body.getReader() loop, append each token to the answer bubble as it arrives
 - Claude provider: use stream: true in the Anthropic messages call

 Effort: ~1 day. No new dependencies.

 ---
 🚀 Leap 2 — Local Document Upload (PDF, DOCX, ZIP, MD)

 Removes the crawling requirement entirely. Users drag-drop their own docs.

 What it enables: Someone with a folder of API specs, runbooks, onboarding docs, or exported PDFs can index them in 30 seconds without configuring a portal URL. This is the "Notion AI for your own files" use case.

 What changes:
 - New "Upload Documents" section in the setup wizard OR a persistent "Add docs" button in the chat UI sidebar
 - POST /api/docs/upload endpoint (multipart) — accepts PDF, DOCX, MD, TXT, ZIP
 - PDF text extraction: pdf-parse npm (pure JS, no native build needed)
 - DOCX extraction: mammoth npm (pure JS)
 - ZIP: unzip with adm-zip (pure JS), process contained docs
 - Files saved to docs/uploads/<filename>/ with a synthetic manifest entry
 - Existing ingest.js pipeline picks them up — no changes to embedder/store
 - UI shows upload progress and "indexed N chunks from filename.pdf"

 Effort: ~2-3 days. Three pure-JS deps.

 ---
 🚀 Leap 3 — Incremental Re-crawl (Change Detection)

 Full rebuild from scratch on every run is the #1 operational pain point.

 Current state: ingest.js re-processes every manifest entry on every run. crawl.js re-fetches every page. No checksums anywhere.

 What changes:
 - Crawl side (src/crawler/crawl.js): compute MD5(html) for each saved page. Add contentHash field to manifest entries. On re-crawl, skip fetch + save if hash matches data/crawl_hashes.json (URL → hash map). Write changed pages only.
 - Ingest side (src/ingestion/ingest.js): read data/ingest_hashes.json (file → hash). Skip embedding if contentHash matches last run. Upsert only changed chunks.
 - Result: Typical re-crawl on a large portal (500 pages, 5% changed) drops from 45 min → 3 min.
 - New CLI: npm run crawl -- --incremental (default after first build; --full to force)

 Effort: ~1-2 days. Uses built-in crypto.createHash('md5').

 ---
 🚀 Leap 4 — Multi-Source Integration via OAuth (Confluence, Google Drive, Notion)

 Removes the portal-URL + credentials requirement. Users connect apps they already use.

 What it enables: A user clicks "Connect Confluence", OAuth flow runs in a browser window (no credentials stored), the app fetches pages directly from the Confluence REST API. Same for Google Drive and Notion.

 Architecture:
 - New integration wizard step: radio cards — "Web Portal (crawl)" | "Upload Files" | "Confluence" | "Google Drive" | "Notion"
 - Per-integration adapter pattern: src/integrations/confluence.js, src/integrations/gdrive.js, etc.
 - Each adapter implements fetchPages() → returns { title, url, html, metadata }[]
 - OAuth flow via Playwright or Electron shell (open browser → get token → save to config)
 - Confluence: uses Space Key + page tree via REST API (no crawling, structured data, faster)
 - Google Drive: fetch Docs/Sheets as exported HTML; index folder recursively
 - Confluence adapter is largely portable from cr2 — it already has the REST API logic

 Effort: ~1 week per integration. Confluence first (most requested for enterprise).

 ---
 🚀 Leap 5 — Evaluation Harness + Analytics Dashboard

 The only way to know if the knowledge base is actually good. Enterprise buyers need this.

 What it enables: After N queries, see: answer rate %, top unanswered questions (documentation gaps), which sections are referenced most, average confidence scores, latency trends.

 What changes:
 - src/rag/query.js: append each query result to data/eval.jsonl — { ts, question, topSemScore, latencyMs, blocked, sectionsUsed, chunkIds }
 - src/rag/eval.js (port from cr2, already built there): CLI with --blocked (gap analysis), --summary, --tail N
 - New "Analytics" tab in the chat UI (public/index.html):
   - KPI row: answer rate, avg confidence, avg latency, total queries
   - Top 10 unanswered questions (blocked queries)
   - Most-referenced sections bar chart
   - Last 20 queries with score badges
 - The "blocked queries" list is the most valuable thing — it tells users exactly what documentation they're missing

 Effort: ~2 days (eval.js exists in cr2; Analytics tab is new HTML/CSS/JS).
