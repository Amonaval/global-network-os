RAG Architecture: LLM Engine Choice & Use Case Diagrams

Does swapping Ollama for Claude Sonnet change your retrieval strategy? How is an individual professional's RAG pipeline different from an organization's? Seven diagrams answer both questions with concrete architecture maps — current state, future state, and per-persona flows.

Core finding: Engine change matters selectively. Upgrading the LLM improves generation quality and unlocks agentic patterns — but retrieval quality is governed by your embedding model + BM25 + reranking pipeline, which is LLM-independent. Upgrading from nomic-embed-text to BGE-M3 will improve retrieval results more than swapping Ollama for GPT-4o. The two axes are orthogonal.

Diagrams 5 · 6

Use Case Flows: Individual Professional vs. Organization

The same retrieval foundation, but radically different query patterns, infrastructure needs, and LLM tier requirements.

Individual Professional

Aarav · Anjali · Marcus · Dr. Priya

Engine recommendation for individual Cheap model (Haiku/Ollama) for chunk enrichment at ingestion. Mid-tier model (Sonnet) for HyDE + generation at query time. No graph DB. No shared infrastructure. Zero-infra constraint is non-negotiable — these users cannot manage Neo4j.

Organization / Team

Future Stage 3 · Multi-user deployment

Engine requirement for organization Frontier model required — GraphRAG entity extraction quality breaks below Sonnet/Opus class. Agentic loop reliability requires strong instruction-following. Infrastructure overhead (Neo4j, Redis, ACL layer) is only justified at team-scale query volume.
