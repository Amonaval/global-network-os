Concept

What is a VS Code Extension?

VS Code is built on Electron — a desktop shell running Chromium + Node.js. Extensions are Node.js packages that run in a dedicated sub-process called the Extension Host, completely separate from the main VS Code renderer process. Think of it as a sandboxed Node server attached to the editor.

When you install an extension, VS Code unpacks a .vsix archive into ~/.vscode/extensions/ and starts loading it on next launch (or when an activation event fires). The Extension Host runs your compiled JavaScript, and you can do anything Node.js can do: read files, make HTTP requests, spawn child processes, manage state.

The two worlds inside an extension

Extension Host (Node.js)
Where extension.ts compiles to and runs. Full Node.js — can use http, fs, any npm package. Calls VS Code APIs (vscode.*) to register commands, create panels, read settings.
WebviewPanel (Chromium sandbox)
A sandboxed browser iframe. Runs your HTML/CSS/JS for the sidebar UI. No Node.js access, no direct internet access (CSP blocks external hosts). Communicates with the Extension Host only via postMessage.
💡
Why this matters for us: The HTTP call to Knowledge Hub happens in the Extension Host (Node.js), not in the webview. That means no CORS issues — Node's http module makes a server-to-server call. The webview just shows the result.
Internals

How the Extension Wires Together

Trace a single question from keystroke to answer:

1
VS Code loads the extension
When the sidebar panel is opened, VS Code fires the activation event and calls activate(context) in out/extension.js. This registers the KnowledgeHubViewProvider against the view ID knowledgehub.chat declared in package.json.
2
VS Code calls resolveWebviewView()
The first time the sidebar panel becomes visible, VS Code calls this method on our provider. We set enableScripts: true and inject the sidebar HTML — the entire question/answer UI lives as a template string inside this method.
3
User types a question and presses Enter
Inside the webview (sandbox), the JS calls vscode.postMessage({ type: 'ask', question }). This is the only way out of the sandbox. No HTTP, no Node, just a message bus.
4
Extension Host receives the message
The onDidReceiveMessage handler fires. We call _handleAsk(question). First we post { type: 'thinking' } back to the webview (shows the spinner), then we read the configured server URL from VS Code settings via vscode.workspace.getConfiguration('knowledgehub').
5
Node.js makes the HTTP POST
_postChat() uses Node's built-in http (or https) module — no npm dependency — to POST { question, sessionId } to http://localhost:3000/api/chat. The session ID persists across the VS Code session so the conversation has memory, same as the web UI.
Extension Host → Knowledge Hub Server
POST http://localhost:3000/api/chat
Content-Type: application/json

{
  "question": "How do I configure Confluence OAuth?",
  "sessionId": "vscode-l9x4k2"
}

// Response
{
  "answer": "To configure Confluence OAuth, go to...",
  "sources": [{ "section": "Confluence Setup", ... }],
  "sessionId": "vscode-l9x4k2"
}
6
Knowledge Hub processes the query
The Express server runs query() — hybrid BM25 + vector retrieval, confidence gate, context compression, then sends to Ollama. The answer returns as JSON. The query is also written to eval.jsonl, so every VS Code question enriches the IDS.
7
Answer flows back to the webview
Extension Host posts { type: 'answer', question, answer } to the webview. The webview's window.addEventListener('message') handler receives it, removes the spinner, and renders the answer. Done.
Packaging

What Gets Published to the Marketplace

Running vsce package bundles the extension into a .vsix file (a renamed zip). Here's what's inside — and what isn't:

knowledge-hub-0.1.0.vsix ← the zip you upload/install
├─ package.json ← extension manifest (name, commands, settings, contributes)
├─ README.md ← shown on the Marketplace listing page
├─ out/
│ └─ extension.js ← compiled TypeScript (the only code that runs)
│ └─ extension.js.map ← source maps for debuggability
├─ media/
│ └─ sidebar-icon.svg ← activity bar icon
NOT included (excluded by .vscodeignore):
✗ src/ (TypeScript source — stays on your machine)
✗ node_modules/ (devDependencies only — typescript, @types/vscode — not shipped)
✗ tsconfig.json, .vscodeignore
📦
Zero runtime npm dependencies. Our extension uses Node's built-in http module for the HTTP call. node_modules/ contains only dev tools (TypeScript compiler, vsce itself) — none of it ships in the package. The .vsix is under 100 KB.

The package.json manifest — what each field does

contributes.viewsContainers
Registers a new icon in VS Code's Activity Bar (the left icon strip). Clicking it opens our sidebar panel group.
contributes.views
Declares the knowledgehub.chat webview view inside our container. type: "webview" tells VS Code to call resolveWebviewView on our provider.
contributes.commands
Registers knowledgehub.openChat and knowledgehub.askSelection. Commands are callable from Command Palette (Ctrl/Cmd+Shift+P) and the right-click context menu.
contributes.menus
Wires askSelection into the editor right-click menu, shown only when there is a text selection (when: "editorHasSelection").
contributes.configuration
Declares the two settings: knowledgehub.serverUrl and knowledgehub.defaultSection. VS Code surfaces these in Settings UI automatically.
activationEvents: []
Empty array = VS Code activates the extension lazily when the view is opened, rather than on every editor startup. Keeps startup fast.

Development

Testing Locally — No Marketplace Required

Method 1 — F5 Extension Development Host (fastest, for active development)

This is the standard VS Code extension dev loop. It opens a second VS Code window with your extension loaded.

1
Open the extension folder in VS Code
Open the vscode-extension/ folder (not the project root) as a VS Code workspace.
code D:\AI\AI_Learning_Projects\poc-ai-learn-rag\vscode-extension
2
Install dev dependencies
These are only used at build time — TypeScript compiler and vsce. They don't ship in the extension.
npm install
3
Press F5 (or Run → Start Debugging)
VS Code compiles TypeScript, then opens a new Extension Development Host window. This is a full VS Code instance with your extension installed and active. Any changes you make to src/extension.ts → save → Ctrl+Shift+F5 to restart the host.
4
In the new window: click the book icon in the Activity Bar
The Knowledge Hub sidebar opens. Make sure your Knowledge Hub server is running on http://localhost:3000 and ask a question.

Method 2 — Install the .vsix file (closest to real install, for QA)

Build a .vsix package and install it directly in your main VS Code. This is exactly what a user does when they install from Marketplace — same code path, no development host.

# From vscode-extension/
npm install
npm run compile

# Build the .vsix
npx vsce package

# Install it in VS Code
code --install-extension knowledge-hub-0.1.0.vsix

# To uninstall when done testing
code --uninstall-extension knowledge-hub.knowledge-hub
⚠️
You need your Knowledge Hub server running when testing. The extension is a thin client — it has no logic of its own. Without http://localhost:3000 responding, you'll get the error state in the panel. Start the server first: node src/api/server.js from the project root.
Knowledge Hub server running on port 3000 node src/api/server.js
Ollama running on port 11434 ollama serve
Extension connects but no chunks found Run setup / upload docs first

Infrastructure

What Needs to Keep Running in Production?

The VS Code extension is a passive client — it has no server of its own, no cloud dependency, nothing to host. What needs to run is the Knowledge Hub stack the extension connects to. Here's the complete picture:

Knowledge Hub server
The Express app (node src/api/server.js). Needs to be reachable at the URL configured in knowledgehub.serverUrl. This is the only thing the extension actually talks to.
Ollama
The local LLM runtime (ollama serve). Listens on port 11434. Knowledge Hub calls it — the extension never does directly. Needs a pulled model: ollama pull llama3.
Vector store
LanceDB files on disk, read by the Knowledge Hub server. No separate process — it's just a directory. Needs to have been populated by running setup / ingestion first.
VS Code extension itself
Runs inside the user's VS Code. No hosting needed. Installed once from Marketplace (or .vsix), stays installed.

Consumer Guide

Installing the Extension — For Someone Who Has Never Done This

You do not need to know TypeScript, Node.js, or anything about how extensions are built. If you have VS Code and a running Knowledge Hub server, this takes 3 minutes.

1
Open the Extensions panel in VS Code
Press Ctrl+Shift+X (Windows/Linux) or Cmd+Shift+X (Mac). A panel opens on the left showing installed and searchable extensions.
2
Search for "Knowledge Hub"
Type Knowledge Hub in the search box. The extension published by knowledge-hub appears. Click the green Install button. VS Code downloads and installs it in seconds. No restart needed.
3
Set your server URL (if not using localhost)
Open Settings (Ctrl/Cmd+,), search for Knowledge Hub. Set Server URL to wherever your Knowledge Hub server is running. If it's on your laptop, leave it as http://localhost:3000. If it's on a team server, enter that IP/hostname.
4
Click the book icon in the Activity Bar
The Activity Bar is the icon strip on the far left of VS Code. A book icon appears — this is Knowledge Hub. Clicking it opens the sidebar panel. Type a question and press Enter.
Consumer Guide

Using It Day-to-Day

Asking questions in the sidebar

Click the book icon → type your question → press Enter. The answer comes from your organization's documentation, processed through the same RAG pipeline as the web UI. The sidebar remembers conversation history within your VS Code session.

Asking about selected code

Select any text in the editor (a function, a class, an error message). Right-click → Knowledge Hub: Ask about selection. The selected text is sent directly as a question — useful for "explain what this does" or "does our docs cover this pattern?"

Keyboard shortcut (optional setup)

To open the chat panel quickly, open the Command Palette (Ctrl/Cmd+Shift+P), type Knowledge Hub: Open Chat. You can bind this to a key shortcut in VS Code Keybindings.

Changing the server URL

If the panel shows a "Could not reach Knowledge Hub" error: your server isn't running, or the URL is wrong. Click the Update server URL link in the error message — it takes you directly to the relevant setting. Check that node src/api/server.js is running in a terminal.

What's happening behind the scenes (for the curious)

Every question you ask through VS Code is logged to eval.jsonl on the Knowledge Hub server — the same store that powers the Intelligence Density Score. Meaning: using the extension actively makes the intelligence layer richer for everyone on your team. The more you use it, the better it gets.

At that rate, Documentation Gaps surface within 2 weeks, Knowledge Risk is visible in 4 weeks, and IDS typically crosses 0.7 (the moat threshold) within 30–60 days of consistent use.
