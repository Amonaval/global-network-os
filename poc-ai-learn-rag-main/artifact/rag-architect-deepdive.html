The stack, end to end

A request enters at the top and falls through four layers to two shared foundations. Everything above the RAG engine is transport; the intelligence lives in the engine and its two dependencies.

1 · UI layer

frontend/src

React 19 + TypeScript, built by Vite as a two-page app. State is split deliberately: Zustand owns client/UI state, React Query owns everything that comes from the server — so caching, refetch, and loading states are never hand-rolled.

Two entry points

index.html → the assistant (chat + 15 panels); setup.html → the 5-step wizard. No router — navigation is the two pages plus an activePanel switch.

State split

appStore.ts (session, sections, pinned chunks, theme) and wizardStore.ts for the form. Server data flows through useApi.ts hooks over React Query.

Streaming

useStream.ts's readStream parses SSE token / phase / log / done / error events — reused by both chat and the setup build.

Legacy shadow

public/*.html + js/ is the pre-React vanilla build of the same screens. Superseded, but its CSS is still shared. A cleanup candidate.

2 · Backend / API layer

src/api/server.js

One ~2,800-line Express server, port 3000, doubling as the SPA host (catch-all GET *). Endpoints group into six concerns. Long-running work (crawl, build, pre-login) is spawned as child node processes and streamed back over SSE so the UI shows live phase + log output.

3 · RAG layer

src/rag

The classification matters: this is Hybrid Retrieval RAG — not naïve single-vector RAG, and not (yet) agentic tool-using RAG. Two retrievers, one fusion, one gate, one compressor. The LLM-augmented endpoints (summaries, outlines, onboarding) are single-shot calls, not tool loops.

Reciprocal Rank Fusion

score = Σ 1/(k+rank), k=60. Combines BM25 and cosine ranks so keyword-exact and semantic hits both surface. HYBRID_WEIGHT=0.5 selects the blend.

BM25 parameters

In-store implementation, k1=1.5, b=0.75 — the standard Okapi defaults. Query text is passed transiently via setQuery() before search().

Two-signal gate

Passes on semScore ≥ gate or a strong RRF rank (≥0.014 ≈ top-3 BM25) — so filename queries aren't blocked. Plus post-hoc DEFLECTION_PATTERNS.

Compression

Score filter → trigram-Jaccard dedup (>0.60) → greedy fill to ~1800 tokens → [n] tagging matching inline citations. ~30–40% fewer tokens per query.

Codegen (level 2)

codegen.js retrieves with much larger budgets (TOP_K=105, CTX=30k) and builds a file inventory so the model only references files that exist.

Diagnose

diagnose.js prints a 6-step retrieval trace — store stats, dim-match check, raw BM25/semantic top-5, final hybrid result — the fastest way to debug a bad answer.

4 · Vector store / DB layer

src/vectorstore/store.js

A deliberately simple default: JSON on disk, sharded per section, loaded into an in-memory array. No external database to install — the price of local-first. Both retrieval math (cosine + BM25) lives inside the store, so swapping the store means re-implementing retrieval, which is why Pinecone stayed semantic-only.

// one shard per section → vectors_<section>.json
_data: [ { id, text, meta, embedding[768] }, … ]

search(queryVec, topK, filter) {
  cosine(queryVec, rec.embedding)   // semantic rank
  BM25(this._query).score(rec.text) // keyword rank
  return rrf(semRank, bm25Rank, k=60)
}

Dimension safety

Ingest auto-detects a provider/dimension mismatch (768 / 1536 / 2048) against stored vectors and forces a full re-index — you can't accidentally mix embedding spaces.

Section as key

The section is the shard filename, the retrieval filter, and the citation group — one field, three jobs. Migration from a legacy monolithic vectors.json is one-time and automatic.

5 · LLM layer

query.js · llm.js · codegen.js

Provider-agnostic by design: three interchangeable providers, each with streaming and non-streaming callers, selected by LLM_PROVIDER. Local-first (Ollama) is the default so the product runs with zero API keys and no data leaving the machine; Claude and vLLM are opt-in.

The provider fan-out is duplicated across three files — query.js (chat), llm.js (askLlm() for the intelligence endpoints), and codegen.js (code generation). Consolidating these into one caller module is the highest-value refactor in this layer.

!

Model default inconsistency

The Claude default is not the same everywhere: query.js defaults to claude-sonnet-4-20250514, while llm.js and codegen.js default to claude-haiku-4-5-20251001. Chat and the intelligence features can therefore run on different tiers unless CLAUDE_MODEL is explicitly set. Pick one default per use-case intentionally, or centralize it.
