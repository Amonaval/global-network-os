Agentic Retrieval Inside Knowledge Hub

What tool-using, iterative retrieval would look like inside the product — and why it belongs in Stage 3, not earlier.

1 What "agentic" means in retrieval

Today's Knowledge Hub pipeline is a single-shot system: embed the query, retrieve, compress, generate. Agentic retrieval replaces that single shot with a reasoning loop. The model decomposes the question into sub-questions, retrieves evidence for each, grades the evidence quality, and re-retrieves if a sub-question is still unanswered.

This is not a complexity upgrade for its own sake. It solves a specific failure mode: multi-hop questions that require assembling evidence from disconnected documents before a coherent answer is possible.

"Does the dosing protocol in the 2022 Chen trial conflict with the patient profile I uploaded last month?" — this question requires retrieving from two sources, comparing their claims, and synthesizing a judgment. A single-shot system retrieves one chunk. An agentic system loops until both sources are in context.
2 Which personas unlock at Stage 3
Marcus (Lawyer) "Which cases in my library cite the same precedent as Smith v. Jones, and does any of them reach a conflicting conclusion?" — legal research requires traversing a citation graph across multiple indexed documents, not a single retrieval.
Dr. Priya (Researcher) "Do any of my experiment logs contradict the hypothesis in the grant proposal I submitted?" — requires retrieving from experiment logs, the proposal, and potentially referenced papers — three source types, one compound judgment.

Neither of these queries fails today because of poor chunking or weak embedding. They fail because the answer requires holding evidence from multiple documents simultaneously — which a loop-based retrieval architecture enables and a single-shot architecture cannot.

3 Why Stage 3, not now

Agentic retrieval is in RAG_STRATEGY.md as Tier 3 — not because it is unimportant, but because the prerequisites are not yet in place. The reasoning loop amplifies both good retrieval and bad retrieval. If the underlying chunk quality is poor (no contextual enrichment), the loop retrieves poor evidence more thoroughly. If there is no RAGAS evaluation layer, there is no way to know whether the loop improved anything.

Contextual enrichment (Stage 1A) must be proven first — the loop needs high-quality chunks to work with
RAGAS evaluation (Stage 1C) must be in place to measure whether multi-hop actually increases faithfulness and recall
LangGraph orchestration is the right tool here — explicitly deferred to this stage

Claude Code as the Engineering Partner

How agentic AI is actively being used to construct the platform — and what this reveals about the product's own thesis.

1 How the platform is being built

Knowledge Hub is being built with Claude Code — an agentic coding system that reads the codebase, plans changes, edits files, runs commands, and iterates based on results. The entire architecture visible in rag-architect-deepdive.html — 40+ endpoints, 5 RAG pipeline stages, 10 intelligence panels — was developed in an agentic loop with the codebase as its context.

Claude Code is itself a RAG system. It embeds the codebase structure (via file reads and grep), retrieves relevant context for each task, and generates targeted edits — exactly the pattern Knowledge Hub implements for professional documents.

The same retrieval pattern: index the knowledge corpus (codebase) → embed the task query → retrieve relevant context (function definitions, related modules) → generate a grounded, citation-level response (a diff with line numbers).
2 What this proves about the product

Building this product with an agentic AI partner is not just an engineering efficiency choice — it is a proof of the thesis. Every Claude Code session is an example of professional organizational memory being leveraged: the CLAUDE.md files, the company constitution, the decision log, the RAG strategy documents all load into context and shape what gets built next.

The CLAUDE.md operating system functions as a persistent prompt that carries company strategy, product principles, and engineering decisions into every session
Context loading follows the exact same progressive strategy Knowledge Hub recommends to customers: load company → product → engineering, in order of precedence
The memory system at .claude/projects/.../memory/ persists cross-session user preferences — the same compounding behavior IDS measures in customers
3 The token ROI model

Each Claude Code session is not a one-time cost — it is an investment in accumulated codebase context. The .claude/.engineering/SESSION_MEMORY.md, DECISIONS.md, and MODULE_INDEX.md files are the amortized return on that investment. A fresh session that loads these files skips hours of re-derivation.

This is the same compounding behavior Knowledge Hub's IDS formula tracks for customers. Query volume × memory clusters × gap closure = organizational intelligence that grows faster than it costs to maintain.

Prompt cache TTL means recent architectural discussions are retrieved instantly — same as KH's local vector store for hot documents
The 06_TOKEN_ROI.md framework governs what gets built: every capability must have a clear answer to "which customer pays for this and when?"
As KH indexes its own build history, it can eventually answer "why was this decision made?" — the platform becomes self-documenting

The Recursive Advantage:
Building an AI Product with AI

The deepest insight from running both roles simultaneously: the product's thesis and the build method are the same claim tested twice. Using organizational memory to answer questions (the product) is identical to using accumulated codebase context to write code (the build method). If the claim holds under the scrutiny of daily engineering use, it holds for the customer too.

→
Dog-fooding at architectural depth
Every Knowledge Hub feature was designed, reviewed, and iterated using the same intelligence-leverage pattern the product sells. The founders are not guessing that it works — they are the first users proving it.
→
The self-indexing path
When Knowledge Hub indexes its own engineering docs, decision log, and build history, the product begins to answer questions about itself. "What was the architectural decision behind the confidence gate?" becomes an answerable query — from the product's own knowledge hub.
→
The Stage 3 rehearsal
Claude Code's multi-file, multi-step, context-aware editing is a real-world example of agentic multi-hop retrieval. Watching it work across the codebase is a design rehearsal for Stage 3 — agentic retrieval across professional document corpora.
