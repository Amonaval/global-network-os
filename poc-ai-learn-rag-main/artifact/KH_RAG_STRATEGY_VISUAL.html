Not all 2026 RAG trends are relevant. This maps the landscape to our actual customers, their documents, and our architecture constraints.

🧭
The question that governs every RAG decision:
"Which paying customer persona does this improve, and what specific query does it make answerable that currently fails?" If the answer isn't immediate, it's not a current priority.

RAG Pattern Relevance mapped to KH personas
Tier 1 — Critical Now
Adopt before or at first paying customer
Contextual
Chunk Enrichment
Aarav's fragment "it reduced latency by 40%" is meaningless without knowing which client, which project. Anjali's note "switched to this protocol" without patient profile context fails retrieval.
67% reduction in retrieval failures (Anthropic). Wraps existing system — no architecture change, no retraining. LLM prepends 1–2 sentences of document context to each chunk before embedding.
D.12
RAGAS
Evaluation
The confidence gate is the right principle but currently unmeasured. RAGAS (Faithfulness, Context Precision, Context Recall) makes every future retrieval change measurable.
Directly feeds IDS — retrieval quality scores belong in the Intelligence Density Score alongside query volume. Required before first paying customer.
Next
Cross-Encoder
Reranking
After hybrid BM25+Dense+RRF retrieves 20–50 candidates, a cross-encoder re-scores them jointly with the query and selects top 5–10.
For regulated professionals, +10–25% precision directly reduces the probability of a wrong answer surfacing with high confidence — a professional liability event. Self-hosted, ~5ms, zero infrastructure.
D.13
Tier 2 — High Value
Stage 2 after Tier 1 is proven
Document-Type
Chunking
Legal briefs (Marcus): hierarchical/parent-child to preserve clause hierarchy.
Medical notes (Anjali): recursive split with high overlap to preserve diagnostic narrative.
Research papers (Dr. Priya): semantic chunking to respect topic transitions.
NOT AST-based code chunking — see Out of Scope.
D.14
Multimodal RAG
(PDF + Charts)
Anjali's financial statements have key data in tables and charts text-only RAG cannot see. Dr. Priya's papers have results in figures. Marcus's exhibits include PDF tables.
Text-only RAG misses a significant failure mode for regulated professionals. Requires local multimodal embedding model — evaluate against zero-infrastructure constraint (D.1).
Stage 2
HyDE for
Vague Recall
When Aarav asks "what strategy did I use for clients like this?" — vague recall query where his vocabulary doesn't match his documents. Hypothetical answer bridges the gap.
Must be a fallback only — apply when initial retrieval fails the confidence gate, never as default. The gate still evaluates actual retrieved content.
Conditional
Tier 3 — Future Stages
Validate earlier tiers first · incompatible with current constraints
GraphRAG
Legal documents (cases, parties, judges, precedents) and medical records (conditions, drugs, outcomes) have dense entity graphs vector RAG cannot traverse. Enterprise law firms at scale will benefit.
Not now — requires graph DB infrastructure, incompatible with zero-infrastructure constraint. Revisit at enterprise legal/medical self-hosted tier.
Stage 3+
Agentic /
Multi-Hop RAG
"What strategy worked for clients with this profile AND how did the 2022 regulation change affect it?" requires multi-hop — second retrieval depends on first result.
Not now — adds latency and hallucination risk at each hop. Single-hop quality must be proven irreplaceable first.
Stage 3+
Out of Scope — Do Not Pursue
These are correct engineering patterns — for a different product
AST-Based
Code Chunking
Tree-sitter splits at function/class boundaries for code repository traversal. KH indexes code files as documents — appropriate. Treating code as a traversable structural graph is Cursor/Copilot territory.
Sarah's problem is "why did we build it this way?" — the answer is in an ADR PDF, not in the AST.
D.15
Function Call
Graph Traversal
Extracting call graphs, class inheritance, import graphs for structural code navigation. Cursor, GitHub Copilot, Windsurf own this loop with hundreds of engineers and deep IDE integration. We do not compete here. GTM: "Engineering Intelligence Platform" label is explicitly dangerous territory.
D.15
Code Generation
Quality Improvements
Improving code generation accuracy, multi-file context, terminal integration. Not our moat. The Founders Compass: "Not a better code generator. We do not compete here." Our code generation exists as a feature that leverages our intelligence layer — not as a standalone competing product.
Out of scope
