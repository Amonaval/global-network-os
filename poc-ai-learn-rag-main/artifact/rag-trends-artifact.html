Section 01

The Defining Shift: Static Pipelines → Reasoning Loops

Three transitions define the 2025–2026 era. Teams that built naive RAG in 2023–2024 are finding those systems fail on real-world queries that require synthesis, comparison, or multi-source answers.

Shift 01
Hybrid Retrieval Default
BM25 sparse + dense vector search fused via Reciprocal Rank Fusion (RRF) consistently outperforms either alone. Pure vector is no longer the obvious default.
Shift 02
Modular RAG
Chunker, embedder, retriever, reranker, generator are independently replaceable modules. Upgrade one stage without breaking others.
Shift 03
Agentic Absorption
Naive RAG (retrieve-once-then-generate) is now considered insufficient. Production systems in 2026 embed retrieval inside a reasoning loop.

Section 02

Agentic RAG vs Naive RAG

Naive RAG: User query → embed → retrieve top-k → stuff into prompt → generate. One retrieval call, no feedback.

Agentic RAG treats retrieval as a tool the LLM calls — not a fixed pipeline step. The agent decides when to retrieve, what to retrieve, whether the retrieved content is sufficient, and whether to retry.

Key Agentic Behaviors

  • Iterative retrieval — retrieve, read, decide if sufficient, re-retrieve with refined queries
  • Tool-augmented search — web search, database lookup, code execution alongside vector search
  • Self-grading — evaluate retrieved context quality before generating
  • Stateful memory — retrieval results persist across conversation turns
Real example: A support agent answering "Why was my order delayed AND what's the refund policy?" — naive RAG retrieves one answer; agentic RAG issues two sub-queries, retrieves from two knowledge sources, synthesizes.

Section 03

GraphRAG & Knowledge Graph Hybrid

Microsoft Research's GraphRAG (open-sourced July 2024) converts unstructured text into a knowledge graph before querying. Standard vector RAG fails at holistic questions like "What are the main themes across all 500 research papers?" — no single chunk contains that global view.

How It Works

  1. GPT-4 extracts entities and relationships from every document
  2. Leiden algorithm detects communities and generates hierarchical summaries
  3. Local queries → entity-level; global queries → traverse community summaries

Section 05

Reranking: The Underappreciated Precision Layer

Initial vector retrieval casts a wide net (top 20–100 chunks). Reranking uses a more accurate model to re-score those candidates and select the best 5–10. Typically delivers 10–25% additional precision and measurably reduces hallucinations.

Best practice: Retrieve 20–50 → rerank → select 5–10 → feed to LLM. A cross-encoder that jointly processes query + document catches semantic nuances that bi-encoders miss.

Corrective RAG (CRAG) & Self-RAG

Self-RAG fine-tunes the generator to output critic tokens — but requires training data. CRAG adds a lightweight retrieval evaluator that wraps any existing system without retraining the generator.

CRAG Decision Flow

→

→
Correct use context
|
Ambiguous context + web search
|

Key advantage: CRAG does NOT require training the generator. It outperforms Self-RAG on several benchmarks without the training cost. Now integrated natively into LangGraph.

Section 08

Chunking Strategies: 2026 Best Practices

Chunking has outsized impact on retrieval quality that is often underappreciated. A 2025 NAACL study found that semantic chunking's 9% recall improvement over fixed-size is not consistently justified by compute cost.

StrategyDescriptionBest For
Recursive character split400–512 tokens, 10–20% overlap at paragraph/sentence boundariesGeneral-purpose default
Semantic chunkingSplit where embedding similarity drops sharply between sentencesDocuments with clear topic shifts
Hierarchical / parent-childSmall chunks for retrieval precision; fetch parent chunk for contextLong documents
Late chunking (Jina AI)Embed full document first, THEN split token embeddingsCross-references, "as mentioned in section 3"
AST-awareSplit at function/class boundaries via Tree-sitterCode corpora
Late chunking is the most innovative recent approach — by computing embeddings in full-document context, cross-references are preserved in the vector representation.

Section 10

HyDE & HyPE: Query Expansion

HyDE (Hypothetical Document Embeddings): use an LLM to generate a hypothetical answer document, then embed that for retrieval. The hypothesis is semantically closer to real answer documents than a terse query.

HyPE (2025): Inverts the approach — generate hypothetical questions per document at index time, then match query to pre-generated questions. Avoids per-query hallucination risk.

HyDEHyPE (2025)
When it runsQuery timeIndex time
Hallucination riskPer-queryContained at index time
Latency overhead25–60% increaseNone at query time
Best forVague queries, vocabulary mismatchFactual corpora, latency-sensitive

Section 13

Contextual RAG from Anthropic

Announced September 2024; widely adopted through 2025. Before embedding each chunk, Claude prepends LLM-generated context summarizing where this chunk sits in the broader document.

Standard chunk:  "it increased by 12%"  ← meaningless alone

Contextualized:  "This chunk is from Section 3 of a Q3 financial report,
                  discussing regional revenue breakdown — [original chunk text]"

Full Technique Stack

  1. Contextual chunk enrichment (LLM prepends context to each chunk)
  2. Hybrid search (BM25 + dense embeddings)
  3. Reranking (Cohere or cross-encoder)
  4. Increased k (more chunks fed to LLM)
Result: Anthropic reported a 67% reduction in retrieval failures vs standard RAG.

Section 16

RAG for Code & Engineering Intelligence

Code has structure that prose does not — function signatures, import graphs, class hierarchies, call chains. Naive text chunking ignores this structure.

Key Production Patterns

  • AST-based chunking: Tree-sitter splits at function/class boundaries for Python, TypeScript, Go, Rust
  • Code graph augmentation: Function call graphs + class inheritance supplement vector similarity with structural navigation
  • Three-layer index: Graph (dependency traversal) + Vector (semantic) + SQL (metadata: date, author, PR status)
ToolRAG Approach
GitHub CopilotHNSW vector index over local codebase + workspace context; embedding cache invalidation
CursorCodebase index + "Shadow Workspace" that predicts next edit
Claude CodeRAG over project files for context-aware code generation

Section 17

Multi-Hop RAG

Chaining multiple retrieval steps where each depends on the result of the previous one. Required when questions need synthesis across documents, temporal reasoning, or entity disambiguation.

ApproachKey Innovation
ReD-RAGDecomposes questions into sub-questions with explicit rewriting markers
CoRAGTrains iterative retrieval via reformulated sub-queries; 10+ point EM gains on MuSiQue
GDP-RAGAct-Review-Update: retrieve, cross-verify, commit verified result to Trajectory Memory
Only Ask What You Don't KnowGrounded delta planning — tracks known facts, retrieves only for genuine gaps
Key challenge: Each hop multiplies hallucination risk. Best practice: CRAG-style verification at each hop before committing the retrieved fact to the reasoning chain.
