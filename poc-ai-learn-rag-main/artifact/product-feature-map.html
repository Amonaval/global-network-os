How content gets in Ingestion Sources

Knowledge Hub pulls content from three independent sources. All three paths converge on the same chunker → embedder → vector store pipeline. Incremental sync detects content changes via MD5 hashing and re-ingests only changed files.

🌐
Web Crawler
Crawls a base URL to a configurable depth, following internal links. Uses Playwright for JavaScript-rendered pages. Respects robots.txt and rate limits.
Script:npm run crawl
Incremental:npm run crawl:incremental
Hash store:data/crawl_hashes.json
Config: portal URL, depth, URL groups in setup wizard
📄
File Upload
Drag-and-drop upload from the UI. Extracts text from PDF, DOCX, Markdown, and plain text. Each file is assigned to a named knowledge section.
Endpoint:POST /api/docs/upload
Formats:PDF, DOCX, MD, TXT
Index:data/upload_index.json
Extractors in src/ingestion/extractors/
🏢
Confluence Integration
Fetches pages from Confluence Cloud or Server via API token or OAuth. Supports space-level selection and incremental sync. Pages are cleaned and chunked like any other document.
Script:npm run confluence:fetch
Auth:API token or OAuth 2.0
OAuth:POST /api/confluence/oauth/start
Config in setup wizard Step 2 / Step 3
After ingestion, each document is split into chunks (default 400 chars, 50 overlap), embedded using the configured embedding model, and stored as per-section JSON shards in data/vectors_<section>.json.
How you ask questions Chat Interface & RAG Pipeline

The chat interface is the primary interaction surface. Every question runs through the full RAG pipeline before reaching the LLM. Results include cited sources and are logged to data/eval.jsonl for intelligence analysis.

Query pipeline (per question)
1Embed — query is converted to a 768d vector using the configured embedding model
2Hybrid retrieval — BM25 keyword + cosine similarity, fused by RRF (weight 0.5/0.5)
3Priority multipliers — boosted sections ×1.3, ignored sections ×0.4
4Confidence gate — blocks if topSemScore < 0.15 AND topRrfScore < 0.014
5Context compression — deduplicate chunks by trigram Jaccard similarity; fit to 1800 token budget
6LLM generation — system prompt + history (last 8 turns) + compressed context → answer
7Log — question, score, latency, sections, blocked status written to eval.jsonl
UI features
◦Streaming answers via SSE — tokens appear as they generate
◦Source citations — [1], [2] in the answer map to named documents with section + URL
◦Session continuity — up to 8 prior turns sent as context; sessions persist in data/sessions.json
◦Section filter — restrict retrieval to one or more sections from the sidebar
◦Chunk Explorer — inspect raw retrieval results for any query without LLM generation
◦Code generation — separate pipeline via POST /api/code/generate with 30K token context budget
◦Sidebar navigation — switch between chat, intelligence panels, and settings without losing context
The intelligence layer 10 Intelligence Panels

Every panel reads from data/eval.jsonl (the query log) or the vector store, and surfaces a different dimension of organizational intelligence. All panels are accessible from the left sidebar.

📊
Intelligence Dashboard
IntelligenceDashboard.tsx
"Is this knowledge hub making our team smarter over time?"
The single-number summary of platform health. Displays the IDS score (0–1) with a moat threshold at 0.70, a trend sparkline (week-over-week), KPI tiles (answer rate, latency, query volume, gap count, risk signals), team IDS breakdown by user, and a filter bar for time/section/user slices.
GET /api/insights GET /api/team/ids GET /api/intelligence/history eval.jsonl
🔍
Gaps Panel
GapsPanel.tsx
"What are people trying to learn that we haven't documented?"
Clusters blocked queries into documentation gap topics. The enriched view adds LLM-generated priority, trending status, and action recommendations. For each gap, an AI-generated doc outline shows exactly what to write to close it.
GET /api/gaps GET /api/gaps/intelligence POST /api/gaps/outline eval.jsonl LLM (enrichment)
💚
Health Panel
HealthPanel.tsx
"Which sections of our knowledge base are working well, and which are degrading?"
Per-section health score (0–100) based on answer rate, chunk freshness, and query volume. Each section can be set to boost / normal / ignore priority. The AI reviewer generates specific improvement suggestions for low-health sections.
GET /api/health PATCH /api/health/section/:name POST /api/health/review/:name eval.jsonl + vectors
🧠
Memory Panel
MemoryPanel.tsx
"What topics does this team revisit again and again?"
Groups recurring answered questions into topic clusters — the organizational memory. Each cluster shows how many times the topic was queried, example questions, and which section answered it. This is the memory breadth component (×0.20) in the IDS formula.
GET /api/memory eval.jsonl
🏛️
Decisions Panel
DecisionsPanel.tsx
"Why was this built the way it was? What alternatives were considered?"
Extracts architectural decisions from indexed documents using an LLM. Each decision captures context, decision, alternatives, and consequences. Filterable by section and searchable. Results persist in data/decisions.json.
GET /api/decisions POST /api/decisions/extract decisions.json LLM (extraction)
⚠️
Knowledge Risk Panel
KnowledgeRiskPanel.tsx
"What knowledge are we at risk of losing if someone leaves or a section goes stale?"
Flags sections with three risk signals: dead_section (no recent answered queries), single_expert (one user accounts for all queries to this section), and single_point_of_failure (high query volume with zero alternatives). Outputs a risk level per section (critical / high / medium / low).
GET /api/knowledge/risk eval.jsonl + vectors
📈
Insights Panel
InsightsPanel.tsx
"How is the knowledge hub performing across the four dimensions that matter?"
A filterable dashboard (time window, section, user, status, keyword) showing overall success rate, latency distribution, top sections by usage, and a recent query list. The filter bar is shared with the Intelligence Dashboard via FilterBar.tsx.
GET /api/insights eval.jsonl
🔧
Maintenance Panel
MaintenancePanel.tsx
"Which documents have changed on disk since they were last indexed?"
Compares MD5 hashes of currently indexed files against their current state on disk. Surfaces stale files (changed but not re-ingested) and missing files (deleted since indexing). For each stale doc, an LLM can generate specific rewrite suggestions based on what queries are blocked in that section.
GET /api/maintenance/staleness POST /api/maintenance/suggest ingest_hashes.json LLM (suggestions)
📉
Analytics Panel
AnalyticsPanel.tsx
"What are the raw usage numbers — total queries, answer rate, top sections, top blocked questions?"
Aggregated KPI view from eval.jsonl: total queries, answered count, blocked count, average semantic score, average latency, top 6 sections by usage with bar charts, and the top blocked questions deduplicated by frequency.
GET /api/analytics eval.jsonl
🗺️
Knowledge Map Panel
KnowledgeMapPanel.tsx
"How does this topic appear across all of our knowledge sources simultaneously?"
Cross-source synthesis for a topic query — retrieves relevant chunks from all indexed sections simultaneously and synthesizes an LLM-generated summary of how the topic appears across sources. Useful for understanding where knowledge is concentrated vs. scattered.
GET /api/knowledge/map POST /api/knowledge/summary LLM (synthesis)
AI configuration LLM & Embedding Providers

The LLM is a plug-in. Swapping providers requires only a config change — the intelligence layer is not tied to any model. Embeddings are similarly swappable but require a full re-ingest when changed (vectors are stored with the model name for compatibility detection).

Ollama Default
qwen2.5:3b
Fully local. No API key. Best for privacy-sensitive environments. Requires Ollama running at the configured base URL. Codegen uses the same model. Chat and code generation use separate streams.
Claude (Anthropic)
claude-sonnet-4-20250514
Cloud. Requires CLAUDE_API_KEY in .env. Highest answer quality. Note: llm.js defaults to Haiku for non-chat calls; query.js and config.js default to Sonnet for chat. Model is configurable per environment.
vLLM / OpenAI-compatible
configurable
Self-hosted OpenAI-compatible server. Useful for enterprise deployments with custom models. Configure the base URL and model name in app config. Supports both streaming and non-streaming endpoints.
Embedding (default)

nomic-embed-text via Ollama — 768-dimensional vectors, fully local, no API key required. Changing the embedding model requires wiping data/vectors_*.json and re-ingesting all documents. The stored vectors include the model name; a dimension mismatch triggers a diagnostic warning in npm run diagnose.

How it runs Distribution & Deployment
Electron Desktop Primary
A packaged Windows .exe (and macOS .dmg) that bundles the Express server and React frontend into a single installable application. Zero dependencies for the end user — no Node.js, no npm, no server setup.
Build: npm run dist · Run: npm run electron · Builder: electron-builder
VS Code Extension Built, not published
A sidebar extension that surfaces the chat interface inside VS Code. Connects to the running Express server on the configured port. Built and functional; Marketplace publish deferred until Stage 1 validation is complete.
Source: vscode-extension/src/extension.ts · Guide: artifact/vscode-extension-guide.html
npm Server Development
The Express server runs standalone via npm run server. The React frontend is served from the Vite dev server in development (npm run dev:all) or from the built dist/ folder in production.
Dev: npm run dev:all · Prod: npm run build:ui && npm run server
