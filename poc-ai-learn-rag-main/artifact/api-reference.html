Knowledge Hub · API Reference

All Express endpoints served by src/api/server.js. Every streaming endpoint uses Server-Sent Events (SSE). Prefix all paths with http://localhost:PORT.

Source: src/api/server.js Default port: 3000 Auth: none (local-first) Endpoints: 40+

⚡ SSE Event Types (streaming endpoints)

tokenOne LLM output token. Accumulate to build the full answer.
phasePipeline phase update — "retrieving", "ranking", "generating". Show as a progress indicator.
logBuild / ingest progress line. Free-text string. Append to a log panel.
doneFinal payload. JSON body: {answer, sources, sessionId, score}. Close the SSE connection after receiving this.
errorError string. Connection will close; display to user.
Chat & Query
POST /api/chat/stream Streaming SSE chat — tokens stream as the LLM generates them ⚡ SSE ▼
Request body
{ "question": string,         // required
  "sessionId": string,        // optional — continue a session
  "section": string,          // optional — filter to one section
  "sections": string[],       // optional — filter to multiple sections
  "history": Message[],       // optional — prior turns
  "userId": string,           // optional — for IDS attribution
  "pinnedChunkIds": string[]  // optional — bypass retrieval gate
}
SSE events
Fires token events during generation. Fires done with {answer, sources:[{section,title,url,score}], sessionId, score} at completion. Fires error on failure.
Notes
Runs the full RAG pipeline: embed → hybrid retrieval (BM25+dense+RRF) → confidence gate → context compression → LLM stream. Logs to data/eval.jsonl. Use this for all interactive chat UI.
POST /api/chat Non-streaming chat — returns the complete answer in one response ▼
Request body
{ "question": string,         // required
  "sessionId": string,        // optional
  "section": string,          // optional
  "sections": string[],       // optional
  "history": Message[],       // optional
  "userId": string            // optional
}
Response
{ "answer": string,
  "sources": [{section, title, url, score}],
  "sessionId": string,
  "blocked": boolean
}
Same pipeline as /api/chat/stream but blocks until generation completes. Use for CLI integrations or the VS Code extension where streaming is inconvenient.
Setup & Build
POST /api/setup/build Save config, run full fetch + ingest pipeline ⚡ SSE ▼
Request body
{ "config": AppConfig }  // full app config object (see /api/app/config)
SSE events
Streams log events showing crawl and ingest progress. Fires done when complete with chunk count, or error on failure.
POST /api/setup/rebuild Re-fetch + re-ingest with existing saved config ⚡ SSE ▼
No request body. Uses the config already saved on disk. Streams the same log/done/error SSE events as /api/setup/build.
POST /api/setup/cancel Kill any running build job and reset build state ▼
No request body. Returns { "ok": true } immediately after terminating the build process.
POST /api/setup/reset Wipe all indexed data and clear setupComplete flag ▼
Deletes vector store files and resets the setup state. Irreversible — requires a full rebuild to restore. Returns { "ok": true }.

GET /api/setup/test-ollama  /api/setup/test-vllm Verify LLM server is running ▼

ParamRequiredDescription

{ "ok": boolean, "models": string[], "error": string | null }
Document Upload
POST /api/docs/upload Upload files — extracts, chunks, embeds, and stores them ⚡ SSE ▼
Request
Multipart form data. Field name: files. Accepts PDF, DOCX, MD, TXT. The section field names the knowledge section these files belong to.
SSE events
Streams log events per file. Fires done with total chunk count on completion.
GET /api/docs/uploads List all uploaded files with metadata ▼
Response
{ "files": [{ "name": string, "size": number, "section": string, "uploadedAt": string }] }
DELETE /api/docs/upload/:name Remove an uploaded file and its vector chunks ▼
URL-encodes the filename. Removes both the file from disk and all associated chunks from the vector store. Returns { "ok": true, "chunksRemoved": number }.

Intelligence & IDS
GET /api/team/ids Team Intelligence Density Score + per-user IDS breakdown ▼
Response
{ "teamIds": number,           // 0–1 aggregate IDS
  "users": [{
    "userId": string,
    "ids": number,
    "queryCount": number,
    "answeredCount": number
  }]
}
Used by the IntelligenceDashboard TeamIdsSection. The aggregate IDS uses the same computeIDS() formula as the main dashboard.
GET /api/intelligence/history All IDS snapshots with week-over-week deltas ▼
Response
{ "snapshots": [{ "ts": string, "ids": number, "delta": number }] }
Reads data/intelligence_snapshots.jsonl. Used by the sparkline trend component in IntelligenceDashboard.
POST /api/intelligence/snapshot Force an IDS snapshot now (bypasses the 7-day guard) ▼
No request body. Computes current IDS from all signals and appends to data/intelligence_snapshots.jsonl. Returns { "ids": number, "ts": string }.

Health & Sections
GET /api/health Per-section composite health score + user-set priorities ▼
Response
{ "sections": [{
    "section": string,
    "score": number,       // 0–100
    "chunkCount": number,
    "priority": "boost" | "ignore" | "normal"
  }]
}
PATCH /api/health/section/:section Set retrieval priority for a section ▼ 
{ "priority": "boost" | "ignore" | "normal" }
Stored in data/section_config.json. Applied at retrieval time via applyPriorityMultipliers() in query.js.
DELETE /api/health/section/:section Remove all chunks for a section from the vector index ▼
Destructive — cannot be undone without a rebuild. Returns { "ok": true, "chunksRemoved": number }.
POST /api/health/review/:section AI suggestions for improving a low-health section ▼
No request body. Returns { "suggestions": string[] } — LLM-generated recommendations based on which queries blocked in that section.
GET /api/sections All indexed sections with chunk counts and display metadata ▼
Response
{ "sections": [{ "name": string, "chunkCount": number, "displayName": string }] }
GET /api/users Distinct users sorted by query count ▼
Response
{ "users": [{ "userId": string, "queryCount": number }] }

Code Generation
POST /api/code/generate Stream-generate code from a spec + codebase context ⚡ SSE ▼
Request body
{ "spec": string,            // natural language spec
  "sections": string[],      // optional — which sections to pull context from
  "sessionId": string        // optional
}
Notes
Uses a separate code generation pipeline in src/rag/codegen.js with a larger context budget (CTX_BUDGET_CODE = 30000) and output limit (MAX_OUTPUT_TOKENS = 52048). Streams tokens, then fires done.
Config & Status
GET /api/app/config Return app config with passwords redacted ▼
Returns the full AppConfig object from src/config/config.js. Token and password fields are masked. Default LLM: ollama / qwen2.5:3b.
POST /api/app/config Save app config ▼
Accepts an AppConfig body. Validates against AppConfigSchema (Zod), writes to data/config.json, and calls configToEnv() to update process env vars live.
GET /api/app/status Setup status, chunks indexed, last crawled, app name ▼ 
{ "setupComplete": boolean, "chunkCount": number,
  "lastCrawled": string | null, "appName": string }
GET /api/stats System stats — chunks, LLM provider, embedding provider ▼ 
{ "chunkCount": number, "llmProvider": string,
  "llmModel": string, "embeddingProvider": string, "embeddingModel": string }
GET /api/license Current license status and usage KPIs ▼ 
{ "tier": "free"|"pro", "valid": boolean, "expiresAt": string | null,
  "usage": { "queries": number, "users": number } }

Returns { "path": [{ "title": string, "sections": string[], "why": string }] } — an LLM-generated onboarding sequence tailored to the org's indexed knowledge.
GET /api/maintenance/staleness Compare stored file hashes vs. current disk state ▼
Response
{ "stale": [{ "file": string, "section": string, "lastIndexed": string }],

{ "file": string, "section": string }
Returns { "suggestions": string[] } — structural and content improvement recommendations based on what queries have been blocked in that section.
Chunk Explorer
POST /api/chunks/search Direct vector search without LLM — for Chunk Explorer UI ▼ 
{ "query": string, "section": string,  // optional
  "topK": number                         // optional, default 10
}
Response
{ "chunks": [{
    "id": string, "text": string,
    "meta": { "section": string, "title": string, "url": string, "chunkIndex": number },
    "score": number, "semScore": number
  }]
}
Bypasses the confidence gate and LLM. Used by the ChunkExplorer panel to inspect raw retrieval results for debugging.
